# Глава 01. Один пакет в одной LAN

В этой главе мы намеренно рассматриваем маленькую, уже подготовленную локальную
сеть из двух Linux-контейнеров. Такой масштаб позволяет увидеть причинную цепочку,
которая обычно скрыта за одной командой `ping`:

```text
interface → Ethernet frame → IPv4 datagram → ICMP message
       ↘ neighbor cache / ARP ↗
```

После шести независимых карточек вы сможете получить ограниченный packet capture,
прочитать его через TShark и локализовать, на каком шаге локального обмена впервые
исчезло ожидаемое доказательство.

## Граница главы

Входные IPv4- и MAC-адреса лаборатории задаются готовой конфигурацией. Мы считаем
source и destination участниками одной LAN, но пока не выводим это из prefix.
CIDR, subnet mask, выбор gateway и route lookup начинаются в главе 02. Поэтому в
этой главе не нужно вычислять сеть, править routes или обобщать наблюдения на
удалённые узлы.

Курс v1 рассматривает IPv4. ARP и описанный формат IPv4 datagram не являются
универсальным поведением любого IP-трафика: в IPv6 соседние задачи решаются иначе.

## Маршрут

1. `01-01` — различить interface, адреса и вложенные protocol units.
2. `01-02` — поднять и доказать безопасный baseline двух endpoints.
3. `01-03` — разобрать детерминированный synthetic capture по полям.
4. `01-04` — сравнить live cold и warm neighbor-cache paths.
5. `01-05` — локализовать три сбоя, не выдумывая root cause.
6. `01-06` — восстановить полный путь по новому evidence bundle.

Каждая карточка укладывается в 30–60 минут и заканчивается собственным DONE.
Следующую карточку начинать для завершения текущей не требуется.
